# Генерация Python-кода по текстовой задаче

Encoder–decoder Transformer, обученный с нуля на TinySMS. На вход подаётся условие
математической задачи, на выходе — Python-программа с функцией `solve()`.
Лучший подтверждённый результат: **public pass@1 = 61,77% (593/960)** после
дообучения exp09. Использованы только данные задания и собственные checkpoint.

## Быстрый запуск инференса

Откройте [inference.ipynb](inference.ipynb) в Kaggle или Google Colab и запустите
ячейки по порядку. Выберите **одну NVIDIA T4**, включите Internet и в первой
ячейке укажите `MODEL_SOURCE`: каталог модели или ZIP, предоставленный отдельно.
Ноутбук также работает через Kaggle **Save & Run All**; установку зависимостей
нужно оставить внутри него, поскольку запуск начинается в чистом окружении.

В каталоге модели нужны:

- `tokenizer.json` — токенайзер, использованный при обучении;
- `config.yaml` — сохранённая конфигурация обучения;
- `model_best_greedy.pth` или `model_best.pth` — соответствующие веса.

Ноутбук скачивает **только 1919 тестовых вопросов**, кодирует их сохранённым
токенайзером и вызывает `inference.py`. Обучающая выборка и Comet для этого не
нужны. Если тестовый Parquet уже доступен локально, его путь можно указать в
`TEST_PARQUET`.

Результаты: `submission.jsonl` с одной записью `{"code": "..."}` на задачу в
исходном порядке и `inference_metrics.json`. Метрики содержат время генерации
всего теста и время процесса инференса, включая загрузку модели. Ограничение
задания — **180 секунд на одной T4**; ноутбук показывает фактический замер.
Установка пакетов и подготовка теста выполняются перед этим замером. Прежние
прогоны инференса итоговой модели на T4 укладывались в лимит 180 секунд;
ноутбук использует тот же код генерации и сохраняет фактическое время запуска.

## Установка

```bash
git clone https://github.com/Mishaq23/hw2_nlp.git
cd hw2_nlp
python -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
```

На Kaggle/Colab создание venv не требуется. Сохраняйте предустановленный PyTorch
с CUDA: устанавливайте requirements без `--upgrade`. Проверка окружения:

```bash
python -c "import torch; print(torch.__version__, torch.version.cuda); assert torch.cuda.is_available(); print(torch.cuda.get_device_name(0))"
```

На GPU используется **FP32, без AMP**. Код работает на одной видеокарте; выбор
T4 ×2 сам по себе не включает распределённое обучение. Для запуска из терминала
на Kaggle пути можно задать так:

```bash
export CUDA_VISIBLE_DEVICES=0
export TINYSMS_DATA_DIR=/kaggle/working/tinysms_all60_2400k
export HF_DATASETS_CACHE=/kaggle/working/hf_cache
```

На другом компьютере задайте собственные доступные для записи пути. При запуске
обеих стадий в разных сессиях должны сохраняться готовые данные, токенайзер и
полный checkpoint первой стадии. В notebook переменные окружения задавайте через
`os.environ` или `%env`, а не отдельной командой `!export`.

## Архитектура лучшей модели

| Параметр | Значение |
| --- | --- |
| Архитектура | Encoder–decoder Transformer, Pre-LayerNorm |
| Размер модели | **51 484 672 параметра** при словаре 8192 |
| Encoder / decoder | 5 / 5 слоёв |
| `d_model` | 512 |
| Attention | 8 голов, размер головы 64 |
| Позиции | RoPE, theta=10000; self-attention обеих частей, без RoPE в cross-attention |
| FFN | SwiGLU, `d_ff=2048` после gating; входная проекция выдаёт 4096 компонент |
| Dropout / attention dropout | 0.1 / 0.1 |
| LayerNorm epsilon | 1e-5 |
| Embeddings | Общие для encoder и decoder, масштабирование на sqrt(512) |
| Выходная проекция | Связана с embedding, без bias |
| Остальные bias / init std | Включены / 0.02 |
| Loss | Token cross-entropy, ignore_index=-100, label_smoothing=0 |
| Optimizer | AdamW, betas=(0.9, 0.999), eps=1e-8, weight_decay=0.01 |
| Gradient clipping | max_grad_norm=1.0 |
| Инференс | Greedy, KV cache, batch=16, максимум 1024 новых токена, остановка по EOS |

Исходники: [модель](src/model/transformer.py),
[слои](src/model/transformer_layers.py),
[генерация](src/model/generation.py).
Ограничение 1024 относится к генерации; обучающие вопросы и программы не
обрезаются. Размеры модели задаются конфигами, а при дообучении и инференсе
архитектура восстанавливается из сохранённого checkpoint/config.

## Данные

Датасет: `SlavaYus/tinysms_qa_12m`, revision
`b2724689ff079e9c22efd548fe134bfb29036dbb`.
Для лучшего результата использована случайная выборка **2 400 000 исходных строк
из всех 60 train-шардов**, с квотами пропорционально размерам файлов и без
повторного выбора строк. Sampling seed=42, split seed=42, validation_fraction=0.0025.

Подготовка автоматически выполняется в `train.py` и сохраняет только выбранные
данные в Arrow, токенайзер и `metadata.json`. Полный исходный корпус локально не
сохраняется, но исходные файлы нужно прочитать по сети. Временные файлы удаляются
после подготовки. Повторный запуск с совпадающими настройками использует готовые
данные. Число 2,4 млн указано **до фильтрации и разделения**; фактические размеры
train/val/test и квоты каждого шарда записываются в `metadata.json`.

Пустые записи удаляются. Официальные тестовые вопросы исключаются из train/val.
Варианты вопроса с разным регистром или пробелами попадают в одну часть по
стабильному хешу. Test содержит 1919 вопросов; порядок сохраняется.

Токенайзер — общий byte-level BPE со словарём 8192, min_frequency=2. Он обучается
на вопросах и программах из 50 000 train-примеров, выбранных с seed=42.
Пробелы и переводы строк сохраняются. Encoder получает question + EOS, decoder —
BOS + code, labels — code + EOS. Padding labels равен -100.

Стадия дообучения использует **те же** готовые train/val/test и токенайзер.
Переобучать токенайзер перед загрузкой прежних весов нельзя.

## Повторение обучения лучшей модели

Лучший результат получен в **две стадии**: exp08 с нуля, затем exp09 из его best.
Сдаваемые конфиги: [best_train.yaml](src/configs/best_train.yaml),
[best_finetune.yaml](src/configs/best_finetune.yaml),
[best_inference.yaml](src/configs/best_inference.yaml).
Параметры первой стадии заданы в `best_train`; `best_finetune` наследует их
и задаёт настройки дообучения. Исторические `exp*`-конфиги для запуска не нужны.
Comet в best-конфигах отключён, поэтому API key не нужен.

| Параметр | Стадия 1: exp08 | Стадия 2: exp09 |
| --- | --- | --- |
| Старт | Случайные веса | Полный best первой стадии, включая моменты AdamW |
| Train seed | 1 | 2 |
| Batch | 32 | 32 |
| Порядок | Перемешивание train | Новый порядок; группировка по длине в пулах 64 батчей |
| Padding | До максимальной длины батча | До кратного 8 |
| Workers / pin memory | 2 / true | 2 / true; persistent_workers=true |
| Precision / accumulation | FP32 / нет | FP32 / нет |
| `torch.compile` | Выключен | Включён; inductor/default, dynamic=null; fallback при ошибках компилятора |
| Начальный LR | 3e-4 | **3.666241190635664e-5** |
| Scheduler | Cosine, T_max=85000, eta_min=3e-6 | Новый cosine, T_max=30000, eta_min=3e-6 |
| Запуск для повторения | **57 500 шагов**, 115 окон × 500 | До **30 000 дополнительных шагов**, 60 окон × 500 |
| Проверка loss | Каждые 500 шагов | До первого update, каждые 2500 шагов и в конце |
| Выбор best | Greedy val pass@1 каждые 2500 шагов | То же, плюс начальная проверка |
| Лимит времени в конфиге | Нет | 32400 с, включая train/val/compile; финальная проверка выполняется после лимита |

**Как восстановлен бюджет первой стадии.** Исходный exp08 планировался на
85 000 шагов и был прерван около 60 тысяч; на скриншоте Comet видна эпоха 119
примерно у отметки 59k. LR checkpoint, из которого начинался exp09, равен
`7.332482381271328e-5`. При исходном cosine от 3e-4 до 3e-6 с T_max=85000 это
соответствует **57 500 шагам**. Это восстановление по LR, а не прочитанный
`completed_steps` исходного файла. Поэтому `best_train` останавливается на
57 500, но сохраняет **T_max=85000**. Сокращать T_max вместе с бюджетом нельзя:
получится другая траектория LR. Старый полный план доступен через `-cn exp08_swiglu`.

В exp09 LR был уменьшен вдвое относительно исходного checkpoint:
`7.332482381271328e-5 → 3.666241190635664e-5`; новое значение теперь записано
в конфиге. Весь запуск занял **11 352,1 с**. По сохранённым метаданным источник
лучшего результата exp09 имел epoch=25, то есть 12 500 обновлений новой стадии.
План 30k описывает длительность поиска best, а не число шагов выбранной модели.

Команды для обеих стадий из корня репозитория:

```bash
python train.py -cn best_train trainer.device=cuda
python train.py -cn best_finetune trainer.device=cuda
```

Первая команда сама готовит данные и пишет `saved/best_stage1/`. Вторая использует
тот же `TINYSMS_DATA_DIR`, загружает `saved/best_stage1/model_best.pth`, сохраняет
моменты AdamW, начинает новый scheduler и пишет `saved/best_stage2/`.
Имена стадий по умолчанию должны соответствовать этим путям. При повторном запуске
задайте новое имя, чтобы не перезаписать предыдущий эксперимент:

```bash
python train.py -cn best_finetune trainer.device=cuda \
  trainer.finetune_from=/path/to/stage1/model_best.pth writer.run_name=my_finetune
```

Для дообучения нужен **полный `model_best.pth`**, а не облегчённый
`model_best_greedy.pth`. Новый stage меняет порядок данных и не восстанавливает
точную позицию dataloader/RNG старой сессии. Время зависит от GPU и длин батчей;
плановое число шагов не гарантирует завершение внутри лимита Kaggle.
Одинаковые параметры воспроизводят постановку; точное совпадение весов и pass@1
между разными версиями окружения не гарантируется.

`epoch` здесь — **окно из 500 обновлений**, не полный проход по данным. Loader
продолжается между окнами. 57 500 × 32 — 1 840 000 предъявлений первой стадии,
30 000 × 32 — до 960 000 второй, а не столько уникальных новых задач.

## Валидация и checkpoint

Best выбирается по **максимальному greedy pass@1** на фиксированной случайной
подвыборке из 512 validation-задач, seed=42. При равном результате сохраняется
более ранний best. Сгенерированная программа исполняется отдельно; её результат
сравнивается с результатом предоставленного эталонного кода:

```text
abs(prediction - reference) <= 1e-6 + 1e-6 * abs(reference)
```

Ошибка/нечисловой ответ модели дают ноль. Непригодные эталонные программы
исключаются из знаменателя; в сохранённой проверке exp09/exp10 были 491 из 512
пригодных эталонов. Это **локальная метрика относительно кода датасета**, а не
оценка бота с эталонными числовыми ответами. Ограничения исполнителя: timeout=1 с,
память=128 MiB, workers=2. Это отдельные процессы с ограничениями, не полноценная
системная песочница. Генерация на тесте не исполняет полученный код.

В каталоге запуска сохраняются `config.yaml`, `tokenizer.json`, полный
`model_best.pth`, облегчённый `model_best_greedy.pth`, `checkpoint-last.pth` и лог.
Инференсу достаточно весов, config и tokenizer; optimizer не требуется.

## Инференс из терминала

При наличии подготовленного `encoded/test` и исходного токенайзера:

```bash
export TINYSMS_DATA_DIR=/path/to/prepared
python inference.py -cn best_inference \
  inferencer.checkpoint_dir=/path/to/model \
  inferencer.from_pretrained=/path/to/model/model_best_greedy.pth
```

Если предоставлен только полный best, укажите `model_best.pth` вместо greedy.
Размеры архитектуры вручную передавать не нужно. Результат находится в
`data/saved/code_generation/test/predictions.jsonl`; там присутствует `sample_id`.
[inference.ipynb](inference.ipynb) дополнительно проверяет полноту и порядок
0…1918 и экспортирует для бота только поле `code`.

## Логирование

Train/val loss, perplexity, token accuracy, LR, скорость и генерационная валидация
пишутся в лог. В конфигурациях `best_*` Comet отключён. Для графиков необязательно
менять код — задайте переменные `COMET_API_KEY`, `COMET_WORKSPACE` и включите writer:

```bash
python train.py -cn best_train trainer.device=cuda writer.mode=online \
  writer.workspace=YOUR_WORKSPACE writer.project_name=hw2-generation
```

Ключ не хранится в репозитории. На Kaggle его можно передать через Secrets.
Comet не нужен для инференса и не влияет на правило выбора checkpoint.

## Структура и происхождение кода

- `src/datasets/` — выборка данных, разбиение, BPE, collate и batching.
- `src/model/` — Transformer, RoPE, SwiGLU и KV cache.
- `src/loss/`, `src/metrics/` — loss и метрики, включая исполнение val-программ.
- `src/trainer/` — обучение, выбор best и инференс.
- `src/configs/` — гиперпараметры и настройки стадий.
- `train.py`, `inference.py` — точки входа; тренировочные notebook не обязательны.
- `inference.ipynb` — воспроизводимая генерация файла для проверки.
